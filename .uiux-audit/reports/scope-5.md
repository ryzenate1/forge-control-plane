## Open questions for the orchestrator

- **Nodes is the declared reference page and currently does not compile** (`AdminNodes.tsx:200-213`). Should Scope 1 write the target frame against the pre-migration shape or the migrating one? Fixing this slice without deciding that will re-break it.
- **Is "Beacon" a page name or an entity name?** The registry says Nodes; `ADMIN_ALIAS_ROUTES` keeps `/admin/beacons` (`admin-registry.ts:248`); the detail route titles itself "Beacon — Forge Admin" (`app/admin/nodes/[id]/layout.tsx:3`) and its back link says "Beacons". Either the sidebar gains a Beacon concept or the workspace copy changes. This needs one decision, applied in eight files.
- **Onboarding Tokens cannot enrol a node that does not exist yet** (`handlers_capabilities.go:23,434` require a `nodeID`). Is that the intended product flow (Nodes → token → join) or a backend gap? If intended, the registry description "Issue, approve and revoke node onboarding tokens" and keywords "enroll, join, register node" (`admin-registry.ts:157`) misdescribe it, and the page needs a "create node + token together" path.
- **Does a fleet-wide pending-approvals view exist anywhere else?** `listOnboardingTokens` requires a node (`lib/api/onboarding.ts:30-35`) and the page says so (`:184`), but an approval workflow that cannot show what is waiting is not an approval workflow. Needs a product decision before gating.
- **Region is currently derived from location short code** (`AdminNodes.tsx:1012`). Deleting the Regions page, or making `nodes.region_id` real, are both defensible; keeping the page as-is is not, because its counts and its delete guard are both keyed on a column the UI never writes.
