### `components/ui/page-info-disclosure.tsx` (104 lines)
- Renders a 28×28 icon button (`aria-label` + `title`, line 39-50) that opens a `Dialog` of `sections[]`. It is **not** attached to the `<h1>`; it sits wherever the page puts it.
- **Consumers: 5 pages, all in the reference set.** `AdminOverview.tsx:832`, `AdminServers.tsx:182`, `AdminMonitoring.tsx:425`, `AdminActivityLog.tsx:275`, `AdminHealth.tsx:464`. **Zero** Platform-scope pages use it (Settings/Webhooks/Plugins/Billing/Notifications/Mail/Upgrade/Onboarding all substitute hand-rolled explainer `<div>`s — see per-page findings).

- Dialog body uses `h4` for section titles (`:80`) with no `h2`/`h3` above it inside the dialog → heading jump inside the disclosure. **S3** — `components/ui/page-info-disclosure.tsx:80`.
- Section copy is forced to `text-xs` (`:84`) — the whole "operational truth" explanation renders at 12px on a dark surface. **S3** — `:84`.
- **Verdict for Scope 1:** declaring it the standard is safe *mechanically* (a11y-labelled trigger, token colours, no fabricated content), but it carries **no guarantee about content** — nothing binds it to the registry `description`, so a page can pass sections that contradict the sidebar. If it becomes mandatory, it should read `findAdminPage(pathname)` itself.

Consequences: (a) the `PageInfoDisclosure` those pages believe they render does not exist on screen, which is why the widget has only 5 real consumers despite 19 authors; (b) the content is authored twice on the pages that also render the widget inline (`AdminMonitoring.tsx:393` **and** `:425`); (c) `components/admin/admin-page-guides.ts` (186 lines, 21 entries) is a **third, unkeyed copy source** — its entries are typed `PageInfoDisclosureProps` (`:1`) and carry their own `title`/`description` that are not joined to `href`, so they drift from `admin-registry.ts` with no compiler help. **Scope 1 must not declare `PageInfoDisclosure` "the standard" until the frame accepts `info` or the 19 call sites are rewritten — today the prop is a no-op.** (Could not run `tsc` under the read-only constraint; evidence is the prop interface at `admin-ui.tsx:140-161` and the absence of a rest spread at `:163` and `:280`.)

## Open questions for the orchestrator

1. **Plugins: gate or delete?** `capability: "metadata-only"` (`admin-registry.ts:228`) is the only such marker in the registry and nothing consumes it. Making it enforceable (disabled-with-reason rendering) is a registry-wide convention that Scope 1..9 will need; deleting Marketplace/Discover is cheaper but is a product decision. Which?
2. **Two notification backends are live on one route.** `/notification-channels` (legacy, `handlers_notifications.go:19`) and `/notifications/channels` (engine, `handlers_notifications_crud.go:20-35`) both have admin UIs. Consolidating is an API decision, not a UI one — please confirm the engine is the target and the legacy console should be unmounted.
3. **Two mail backends plus one shared cache key.** `/admin/mail/settings` (`handlers_mail_settings.go:12`) and `/admin/settings/mail` (`handlers_settings_extras.go:25`) both persist SMTP. Which is canonical, and should the other be deleted? (This determines whether Settings' Mail tab disappears.)
4. **Does `/admin/onboarding` owe anything to `/setup`?** There are two first-run surfaces with two status endpoints (`app/setup/page.tsx:48` uses `fetchSetupStatus`; `onboarding-manager.tsx:25` uses `/onboarding/status`). Is the admin one meant to replace `/setup`, or should Guided Setup point at node onboarding?
5. **Is `DashHeader` allowed to survive as a page frame?** It emits `<h2>` not `<h1>` (`dashboard-cards.tsx:39`), a hard-coded `text-red-400` eyebrow (`:37`) and a `truncate`d description (`:42`), and its `Sparkline` fabricates a trend for `<2` samples (`:108-120`) — the one component in the product that visibly contradicts `telemetry-ui.tsx:338-344`. 6. **Is `versions.length || 4` (`AdminUpgrade.tsx:83`) deliberate triage or an accident?** It is the clearest "invented number" in the slice; if the intent was "assume 4 when the API is silent", the same intent must be encoded in the other 87 pages, which argues for fixing it in `MetricTile` semantics rather than locally.
