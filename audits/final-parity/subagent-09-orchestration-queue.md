## 2. Structural findings (AF-1..AF-3 required + queue consolidation)

### AF-1 — Durable event pipeline is write-only; outbox guarantee does not exist — **CONFIRMED OPEN, HIGH**

- **Chain:** `eventstore/store.go:214-222` `OutboxPublisher.Publish` does `INSERT events … dispatched=false` then synchronously calls `registry.Publish` (`events/registry.go:144-191` fans out N goroutines, `wg.Wait()` with 30s deadline). No `PublishTx(ctx,tx,env)` exists (`grep PublishTx` zero). Business transactions commit first, then event inserts after (`git/deploy_service.go` style; `dbbackup/service.go:262-284` similar). If process dies between business commit and publish, durable copy absent or orphaned.
- **Relay empty:** `eventstore/outbox.go:39-43` `Relay.Subscribe` → only callers are tests (`store_test.go:362,395`). `http/server.go:148` `EventRelay *eventstore.Relay` wired at `main.go:1519` but zero dereferences. `outbox.go:102-162` `processBatch → ClaimPending(10, lease=330s)` → `deliverWithRetries` over **zero subs returns nil** → `MarkDispatched` within 5s. Every consumer (`fencing.go:20`, `failover/service.go:152`, `trafficmanager`, `loadbalancer`, `heartbeatmonitor` subscribers at `main.go:441,946,1026-1077,1236-1243`) is registered on the in-memory `Registry` only.
- **Cost:** Two writes per publish (INSERT + UPDATE to dispatched) for audit-only durability (pruned `Prune 7d/30d` `outbox.go:95`); cross-instance automation impossible (NodeOffline observed by instance A cannot trigger failover on B).
- **Reference gap:** River `InsertTx` (`client.go:1831-1854`) binds enqueue to business tx; Nomad keeps evals in Raft so broker always replayable. Forge's primitive is River-quality (`ClaimPending FOR UPDATE SKIP LOCKED`, `claimed_until` lease math `(batch+1)*30s`, DLQ, retention) but lacks both ends.
- **Recommendation (P0):** Add `func (EventStore) PublishTx(ctx, pgx.Tx, Envelope) error`; migrate ~10 business-critical publishes (fencing/failover/tm/lb/recovery). Register those subscribers on `Relay` (durable) in addition to `Registry` fast-path. Change `processEvent:156-158` to **not** mark dispatched when `len(subs)==0` (currently writes `"delivered" to nobody`).

### AF-2 — No leader election; ~30 uncoordinated daemons — **CONFIRMED OPEN, HIGH**

- **Evidence:** Inventory §0. Live coordination is comment-level jitter only. The only elector implementation is the dead fork `forge/api/queue/leader.go:23-133` (LeaderConfig TTL 15s, ElectInterval 5s, `LeaderAttemptElect/Resign` via `Executor` interface, `isLeader` atomic, `leaderCh` notify) plus `river_leader` TTL rows (`elector.go:26-31`, `dbsqlc/river_leader.sql:1-60`) — both documented deprecated at `cmd/api/river.go:13-20` and `queue/doc.go:1-5`.
- **Wiring gap:** `queue.Service.Start:124-130` + `operation.Service.Start:157-167` each run 5 workers plus `reaper:169-188`, `periodic tick:95-107`, `hbm EvaluateAll:127-181`, `rec reconcile:697-719`, `ep Start:101`, `failover loop:554-580`, `replicamanager reconcile:697-719`, etc. Failover `lastAction` map (`failover/service.go:97-100,446-453`) is in-memory cooldown — two replicas each see first failure in window and both run `runFailoverAction` (`main.go:862-924` which itself spawns a `go func` 2-hour context without leader gate).
- **Reference gap:** Nomad `leader.go:413-430` gates deploymentWatcher/volumeWatcher/periodicDispatcher under leadership (revoked `1445-1454`); River gates maintenance on `river_leader` row. Forge has `store_failover.go:130-165` advisory-lock `CreateFailoverIncident` as proof-of-pattern applied once.
- **Recommendation (P0):** Introduce `forge_leader` TTL table or `pg_try_advisory_lock(hashtext('forge-leader'))` election wrapper gating maintenance-class daemons (reconciler, periodic, evacuation sweep, retention prune, failover loop, backup retention worker). Keep per-event work on `SKIP LOCKED` claims without leader. Resurrect `queue/leader.go` elector; wire in `main.go` alongside `eventRelay`.

### AF-3 — Fencing writes tokens nothing enforces, fires on wrong edge, duplicated — **CONFIRMED OPEN, HIGH**

- **Wrong edge:** `fencing.Service.Handle:20-27` switches only on `EventNodeRecovered` (`heartbeatmonitor/service.go:340` emits on `Healthy` recovery). Real partition window is **before** recovery — unfenced. NetBird revokes on policy removal via next `NetworkMap` push (`account.go:457`) — enforcement is immediate, not post-recovery.
- **Unenforced:** `fencing.go:34-41` `FenceNode` loops `ListServersForNode` → `Generation++` + 24h leaseExpiry → `UpdateServerGeneration`. `recovery/service.go:642-650` duplicates per-server bump with 1h lease + rollback `UpdateServerGeneration(prevGen, prevLease)` `653-657` and `670-677` `errors.Join`. Read side is near-zero: `reconciler/service.go:559-565` stale-workload counter only. `beacon/internal` grep for `generation|fence` yields zero (except logrotate). Power ops `clustermanager/service.go:671-678` builds `CreateServerRequest{Target: {NodeID, …}}` without passing `generation`; `beacon/server.go:735-842` create/power handlers never read a generation token.
- **Duplicated & racing:** Two writers race; last writer wins; leases differ 24h vs 1h. No CAS precondition on `UpdateServerGeneration: store_servers.go:502-506` (`UPDATE servers SET generation=$2 … WHERE id=$1` unconditional). Six controllers can act on same unhealthy server within one interval: reconciler desired-vs-actual (`reconciler/service.go:523-535`) + health-recovery restarts (`581-676`) + replicamanager replacement (F6) + crashdetector auto-restart (`main.go:947-970`) + failover evacuate/restart (`862-924`) + recovery restore (`recovery/service.go:335-372`).
- **Recommendation (P0→P1):** Collapse to single `fencing.Service.Fence{Server,Node}(ctx, id) (newGen, error)` with CAS `WHERE generation=$old` (add `generation` param to store). Make every act path (`RequestServerPower`, dispatch, migration) send `generation` and reject `stale_generation` at beacon via handler field. Reuse same column as per-server act lock for AF-4 serialization (`WHERE generation=$n` on status writes), mirroring Kubernetes `resourceVersion` / Nomad `modify-index`.

### Queue consolidation verdict — **DO NOT ADOPT RIVER; consolidate to `queue.Service` as sole writer**

Same `UniqueSkippedAsDuplicate` signal absent in both (`ON CONFLICT DO NOTHING`).

## 3. Additional logic findings re-verified (to reach >=4)

**Q-STILL-01 — Cancel regresses terminal jobs (P0, `queue/store.go:113-130`):** `Fail` predicate absent. Cancelling completed → `failed`; instance B succeeds → `Acknowledge` overwrites cancel to `completed`. Referenced by `MASTER_FINDING_INDEX REF-ORCH-Q-01`. Fix: `WHERE id=$1 AND status IN ('pending','running','retrying')` + rowcount check; River `JobSetStateIfRunningMany` pattern.

**Q-STILL-02 — Operation fake backoff (P1, `operation/service.go:288-304`):** `timer := time.NewTimer(backoff)` blocks one of 5 workers while status `retrying` sorts FIRST. Measured effect ≈1s. No `available_at`. Forge's own `queue.retrySQL` solves it. Fix: add `next_retry_at TIMESTAMPTZ` to `operations`, filter `WHERE next_retry_at<=NOW()`; never sleep in worker.

**Q-STILL-03 — Periodic duplication keys diverge (P0, `queue/periodic.go:142`):** `periodic:<id>:<RFC3339Nano>` derived from each replica's `nextRun` (seeded at own start `Add:77-80` `schedule.Next(now)`). Two replicas produce different keys for same logical run → dedupe fails even though idempotency exists. Fix: round `scheduledFor` to period floor or use counter, gate with leader.

**Q-STILL-04 — Non-tx lifecycle tears (P1, `queue/store.go:69-149`):** Each of `Dequeue/Acknowledge/Fail/Retry` runs 4 independent `Exec`s on pool (operations/step/attempt rows). Crash mid-sequence → `job_queue` pending→running while `operations` still `queued`. River centralizes via `JobSetStateIfRunningMany`. Fix: wrap in `pool.Begin / Commit`; test with fault injection.

**Q-STILL-05 — Silent de-durabilization fallback (P2, `services/dbbackup/service.go:262-284` logic preserved via main.go operation handlers 603-672):** Storage restore path downloads before beacon call; on queue failure original HTTP path fell back to `go runRestore` with no retry/visibility. Now operation-backed handlers retain same verify-then-dispatch but still lack `EnqueueTx`. Fix: fail request on queue error; callers retry with same idempotency key.

**R-STILL-06 — Beacon heartbeat liveness for queue (P1, `queue/queue.go:213-226`):** `keepLease` uses `jobCtx` (worker context) for `Heartbeat`. On graceful `Stop:132-142` context cancels → heartbeats stop → leases lapse 30s → another replica steals jobs whose handlers still draining. `operation/service.go:500-504` already fixed sibling via `context.WithoutCancel`. Port same.
