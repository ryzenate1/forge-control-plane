## 3. High-Impact Logic Findings (8 — ≥4 required)

### BKP-08-01 — Unauthenticated sidecar + nil AAD → cross-server transplant forgery | P0
- **Evidence:** `beacon/local.go:787 writeMetadata` writes `localMetadata{Checksum,SIZE,Created}` as plain JSON `.metadata.json` (`Chmod 0600` but body unkeyed); `local.go:757 readOrCreateMetadata` returns `metadata.Checksum` verbatim when sidecar exists (no re-hash); `verification.go:64` verifies vs that sidecar; `s3.go:27 checksumMetadataKey="sha256"` stored as S3 user-metadata (unkeyed); `services/backup/encryption.go:26 GetEncryptionKeyFromEnv` bypasses `secrets/keyring.go:75 envelope forge:v1:<keyID>:<b64(nonce||seal)>`, `encryption.go:92 deriveEncryptionKey(master,nil,purpose)` nil salt + single purpose `gamepanel-backup-encryption:18`, `encryption.go:119 gcm.Seal(nil,nonce,data,nil)` nil AAD; `backup.go:59 BackupInterface` trusts caller-supplied `namespace/name` (`validNamespace:112`/`validBackupName:125` charset/length only).
- **Effect:** Attacker with write to local FS or shared S3 bucket can overwrite `backup.zip` + sidecar/metadata consistently; `VerifyBackup:66 EqualFold` passes. Even without sidecar tamper, GCM nil AAD means ciphertext for `server-A/backup-20260101T000000Z.zip` validates identically under `server-B` if name spoofed → silent cross-tenant restore of wrong-server data. Restic avoids via content-addressed IDs, Kopia binds content IDs.
- **Fix:** Per-backup AAD `serverID:backupName:uuid` in `gcm.Seal/Open`; derive subkey `HKDF(activeKey, serverID\|uuid, salt=random16)`; store `nonce||ciphertext` envelope with `keyID` header (use `keyring`); on `Restore` re-hash file vs DB checksum *and* AEAD tag, ignore sidecar if mismatch (fail closed, remediation log).

## 4. Cross-Cutting Concerns

### Scheduling — Beacon gocron vs Worker policyDue
- **Current:** Dual schedulers with different persistence (`Worker` persists `next_run_at` via `persistNextRun:166` `cronParser.Parse`; beacon `jobs map[string]*gocron.Job` in-memory, rejects duplicate `serverID:55`). `policyDue:152` returns `false` if `NextRunAt==nil` → first creation never runs until manual `persistNextRun` (1-min delay). `Worker loop:95` holds tick synchronously while `pickupBackupJobs:182` loops 5 jobs × 20 min → blocks ticker.
- **Reference delta:** Kopia `NextSnapshotTime(previousSnapshotTime, now)` earliest among interval/ToD/cron; Forge only single cron Interval vs Kopia union of `IntervalSeconds+TimesOfDay[]+Cron[]`. No `RunMissed` catch-up on restart.
- **Wire fix:** Single scheduler (Worker), deprecate beacon gocron, add catch-up: if `NextRunAt < now - threshold` fire once then recompute.
